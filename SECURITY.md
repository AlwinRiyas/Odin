# Security Policy

## Supported versions

The latest released version is the primary supported version for security fixes. Older versions may not receive fixes unless explicitly stated in a release note.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability publicly before maintainers have had an opportunity to investigate it.

Use the repository's GitHub security advisory/private reporting mechanism when available. If private reporting is unavailable, open an issue without including exploit details and request a private disclosure channel.

Include:

- affected version
- affected component
- clear reproduction steps
- security impact
- suggested remediation, if known

Do not include credentials, personal data, or unrelated sensitive information.

## Response expectations

Security reports will be triaged based on severity and reproducibility. Once a fix is available, the affected release and security impact will be documented in the release notes when appropriate.

## Responsible use

This project is intended for authorized defensive security assessment. Users are responsible for obtaining permission before scanning systems they do not own.
